# AutoTabGroups

**用 AI 理解网页，把当前窗口的未分组标签整理到 Chrome 原生标签组。**

AutoTabGroups 是一个 Chrome 扩展。你可以用快捷键、侧栏或右键菜单整理网页：优先复用已有分组，需要时再建立新组。已经分好组的页面保持原样，何时整理由你决定。

[下载 0.1.3](https://github.com/Miraclexc/AutoTabGroups/releases/tag/v0.1.3) · [使用指南](docs/user-guide.md) · [更新说明](docs/RELEASE_NOTES_0.1.3.md) · [反馈问题](https://github.com/Miraclexc/AutoTabGroups/issues)

## 它能做什么

- **整理一个页面或整个窗口。** 三个明确的动作分别用于当前页、批量归入已有组，以及允许新建组的批量整理。
- **沿用你的 Chrome 分组。** 插件创建的组和你手动创建的原生组都可以作为目标，无需先维护分类库或手动接管。
- **用模型理解归属。** 根据网页信息、组名和分组说明判断主题，不需要编写域名、关键词或网址规则。
- **保留人工决定。** 已分组页面不参与自动分类；需要纠正时，可以手动改分、编辑分组或撤销最近变更。
- **按需读取正文。** 默认只使用基本描述；也可选择内置正文提取、Tavily Extract 或 DeepSeek Fetch。
- **按自己的习惯使用。** 侧栏负责日常操作，独立配置页管理服务与偏好；支持中文、English、浅色、深色和跟随系统。

扩展直接连接你配置的模型与读取服务，无需单独部署后端。自动整理需要可用的模型 API；手动建组不依赖模型。

## 安装

### 下载发布版

需要 **Chrome 140 或更高版本**。

1. 前往 [Releases](https://github.com/Miraclexc/AutoTabGroups/releases)，下载 `auto-tab-groups-0.1.3-chrome.zip`。
2. 将 ZIP 解压到一个准备长期保留的文件夹。
3. 打开 `chrome://extensions`，启用右上角的“开发者模式”。
4. 点击“加载已解压的扩展程序”，选择解压后直接包含 `manifest.json` 的文件夹。
5. 在 Chrome 工具栏固定 AutoTabGroups，点击图标打开侧栏。

GitHub 自动提供的 **Source code** 压缩包是源码，不能直接作为扩展加载。请下载 Release 附件中的插件 ZIP。

### 更新已有安装

将新版解压到原加载目录，覆盖旧文件，然后在 `chrome://extensions` 点击扩展的重新加载按钮。关闭已经打开的旧侧栏或配置页，再重新打开。

更新前可以在“配置 → 高级 → 数据与诊断”导出配置与分组说明。导出不包含密钥。**不要先卸载扩展**，卸载会清除本地配置。

## 第一次使用

1. 点击工具栏图标打开侧栏，再点击右上角的配置按钮。
2. 在“服务 → 标准 Chat 服务”选择平台，填写 API Key。预设会填入服务地址、协议和默认模型；模型名称可以修改。
3. 保持“归组判断服务”复用标准 Chat，先用一套配置开始。
4. 可点击“测试连接”检查当前输入，再点击“保存配置”。测试不会代替保存。
5. 回到有待整理网页的窗口，使用下方三个动作之一。

如果窗口还没有分组，可打开至少三个主题相关的普通网页，再使用“更新分组”初始化。只有一两个页面时，可以先从“本窗口分组 → 手动建组”建立目标组。

## 三个整理动作

| 动作 | 默认快捷键 | 处理范围 | 能否新建组 |
| --- | --- | --- | --- |
| **整理当前页** | `Alt+1` | 当前一个未分组页面 | 不能，只加入已有组 |
| **更新分组** | `Alt+Shift+1` | 当前窗口全部可处理的未分组页面 | 已有组时不新建；窗口完全没有组时允许初始化 |
| **更新并允许新建分组** | `Alt+Shift+2` | 当前窗口全部可处理的未分组页面 | 先匹配已有组，再为剩余页面分析新组 |

三个动作均可从侧栏、网页右键和扩展图标右键执行。同一动作在不同入口遵循相同规则。网页右键中的当前页指触发菜单的标签，批量动作处理它所在的窗口。

快捷键在后台执行，不自动打开侧栏；图标角标和悬停文字反馈任务状态。实际绑定以 Chrome 为准，可在配置页查看，或在 `chrome://extensions/shortcuts` 中调整。旧安装更新后若没有自动分配新快捷键，也可在这里手动绑定。

### 哪些页面会参与

自动整理只处理**触发操作的当前普通窗口中、尚未分组的 HTTP(S) 页面**。固定标签、无痕窗口、浏览器内部页和扩展页不参与，也不会跨窗口搬动标签。

| 你的操作 | 下一次整理时的行为 |
| --- | --- |
| 在组内页面跳转到新网址 | 仍在组内就跳过 |
| 新标签实际进入了某个组 | 跳过，不对它重新分类 |
| 从组内打开链接，但新标签落在组外 | 作为未分组页面参与下一次手动整理 |
| 手动把标签从 A 组移到 B 组 | 保留 B 组，不重新判断 |
| 把标签拖出分组 | 下次整理重新参与，输入未变化时尝试复用缓存 |

浏览器事件只刷新状态，不会自动触发分类。任务执行期间新开的页面等下次处理；候选页面若被关闭、导航或手动分组，会在应用前检查并跳过。

### 分组如何确定

已有组通过当前真实组名与分组说明表达用途。缺少说明时，整理前由标准 Chat 根据组名和最多五个组内参考页面补齐；这个过程不会重新分类现有成员。说明补齐失败会停止本次整理，不会把该组当作不存在。

判断足够明确的页面加入目标组，没有合适目标或分数不足的页面保持未分组。默认最低归组分数为 `0.8`，最小候选分差为 `0.2`，可在高级设置中调整。普通 Chat 的自评分不等于经过验证的正确率。

**AI 新建组至少需要三个最终明确匹配且仍可操作的成员。** 这个门槛不影响向已有组加入单个页面。用户明确手动建组时，一个或两个页面也可以成组。

## 侧栏与配置页

### 侧栏：日常整理

侧栏围绕三张卡片组织操作：

| 卡片 | 内容与操作 |
| --- | --- |
| **当前页面** | 当前标题、页面来源、分组状态，整理当前页或手动指定已有组 |
| **本窗口整理** | 可整理／不参与的数量，点击展开逐页清单与排除原因，执行两个批量动作 |
| **本窗口分组** | 查看真实原生组与成员，定位页面，手动建组，编辑名称、颜色和说明 |

页面清单默认收起。运行时显示进度与取消操作；关闭侧栏不会取消已启动的任务。成功提示以短暂浮层反馈，不挤占卡片布局。

### 配置页：设置与最近整理

配置页在独立标签页中打开，再次打开时复用已有页面。一级导航分为三个标签：

| 标签 | 包含内容 |
| --- | --- |
| **常规** | 主题与语言、实际快捷键、最近整理、使用帮助 |
| **服务** | 标准 Chat、归组判断服务、网页读取方式与凭据、连接测试 |
| **高级** | 归组门槛、输入预算、读取兜底、思考参数、配置备份、缓存和诊断 |

普通参数使用对齐的设置行，连接状态、最近整理和独立维护操作使用卡片。主题与语言即时保存；服务和高级设置共用草稿，修改后点击“保存配置”生效。测试使用当前草稿，不保存配置；测试或保存失败时保留输入。

## 模型与网页读取

### 模型服务

标准 Chat 用于补充分组说明、生成说明草稿、提出新组，也可以承担归组判断。内置以下平台预设：

**OpenAI、Google Gemini、Anthropic（Claude）、DeepSeek、通义千问（百炼）、Kimi（月之暗面）、智谱（GLM）。**

使用预设时无需手填 API 地址。模型是否可用取决于账号权限，可改成账号支持的型号。自建服务、代理或其他区域端点可使用 **OpenAI 兼容**或 **Anthropic 兼容**配置，自行填写地址与模型。

归组判断默认复用标准 Chat；也可独立配置 Chat、Jev 或 OpenAI Decisions。专用决策后端只负责判断归属，说明与新组规划仍需要标准 Chat。这里配置的是平台 API 服务，并非聊天网站的登录或订阅。

### 网页读取

默认使用标题、清理后的网址与页面描述。需要更多上下文时，在“服务”中勾选“读取网页正文”，再选择读取方式：

| 方式 | 用途与配置 |
| --- | --- |
| **内置读取器** | 从当前已加载页面提取正文，无需额外 API；排除表单和可编辑区域 |
| **Tavily Extract** | 将网址交给远程提取服务，需要独立接口地址与 API Key |
| **DeepSeek Fetch** | 使用 Fetch 读取接口，需要独立接口地址与 API Key，不复用 Chat 接口 |

远程读取不附带浏览器 Cookie，因此登录后页面的远程内容可能不同。默认开启本地兜底：远程读取失败后尝试本地正文，再退回基本描述；也可在高级设置中关闭兜底。

正文长度、请求输入预算、读取超时、Tavily 提取深度和模型思考参数均可在高级设置调整。读取选项同样作用于生成分组说明时参考的页面。

## 结果、纠正与撤销

打开“配置 → 常规 → 最近整理”，查看最近一次任务。侧栏不重复展示结果列表，也不累积历史中心。

- **查看结果：** 区分已归组、保持未分组、已跳过和失败；展开查看原因、摘录与候选分数。
- **定位页面：** 激活原标签；已经关闭的页面不会被自动重新打开。
- **纠正判断：** 手动指定当前窗口的已有组，或对选定页面重新判断；重新判断会绕过该页分类缓存。
- **重试失败：** 重新核对页面状态，并沿用原动作的新建权限，不会把普通更新升级成允许新建。
- **撤销变更：** 撤销最近一次有效成员变更；取消或部分失败后，已经完成的变更仍可撤销。

最近任务与撤销记录分开保存。没有移动页面的任务、测试连接和生成说明不会覆盖上一次有效撤销。撤销会跳过用户随后关闭、导航或重新分组的页面；浏览器重启后不能继续使用旧会话撤销。

分组名称、颜色和说明也可从侧栏编辑。“根据组内网页更新说明”先生成草稿，保存后生效；成员变化不会自动重写说明，也不会因此重新整理组内标签。

## 数据与权限

网页信息只在你触发整理、生成或更新说明时发送到配置的模型服务。缺少说明的已有组也可能提供组内参考页面信息。连接测试使用测试内容，不读取你的标签。

选择远程正文读取时，读取服务会收到清理后的网址，受长度限制的读取结果随后交给模型。模型和读取 API 可能按各自服务规则计费。

- 配置、密钥、分组说明与最近任务保存在本机扩展存储；密钥存储不是加密保险库。
- 分类缓存最多保留当前浏览器会话的 300 条判断，**没有固定一小时过期**。网页信息、模型或候选组含义变化后重新判断。
- “高级 → 数据与诊断”可导出配置与说明、预览并导入备份、清除分类缓存。最近任务详情可在“常规 → 最近整理”清除。
- 导出不包含密钥、完整正文或原生标签／分组 ID；导入不会移动标签、建立原生组或恢复关闭的页面。
- 扩展使用标签、原生分组、页面提取、存储、侧栏、右键菜单和任务恢复权限；没有后台持续自动整理或默认云同步。

完整说明见[数据与权限](docs/privacy.md)。

## 从源码构建

开发环境需要 **Node.js 22.12+、npm 10+**。推荐使用 Node.js 24，依赖由项目的 `package-lock.json` 管理。

```sh
git clone https://github.com/Miraclexc/AutoTabGroups.git
cd AutoTabGroups
npm ci
npm run build
```

构建后加载 `.output/chrome-mv3`。常用命令：

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 启动 WXT 开发构建 |
| `npm run check` | 类型检查、Lint、单元测试和生产构建 |
| `npm run zip` | 生成可分发插件 ZIP |
| `npm run mock:server` | 启动本地模型 mock 服务 |

项目基于 React、TypeScript、WXT、Zod 和 Chrome Manifest V3。模型请求、权限校验与标签变更由扩展后台处理；页面提取包含元数据与 Readability 正文读取。测试使用本地 mock，不需要真实付费模型或个人浏览器配置。当前浏览器验收使用 `scripts/usability-regression.mjs`、`scripts/ui-acceptance.mjs` 等脚本，参数和覆盖范围见[测试与验收](docs/manual-testing.md)。
