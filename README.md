# AutoTabGroups

**用 AI 理解网页，把浏览器标签整理成清晰的 Chrome 原生分组。**

AutoTabGroups 是一个 Chrome 扩展。通过快捷键、侧栏或右键菜单，你可以整理当前页面，也可以一次整理当前窗口的未分组网页。模型根据网页内容和分组说明判断归属，优先加入已有组，并在你选择时为相关页面建立新组。

## 主要功能

- **语义归组。** 结合网页标题、网址、描述和可选正文，理解页面与分组的关系。
- **原生分组。** 使用 Chrome 标签组，沿用你已经建立的分类方式，保留手动安排的页面归属。
- **三种整理动作。** 整理当前页、更新本窗口分组，或在更新时为剩余页面建立新组。
- **手动管理。** 选择页面建组，指定页面所属组，编辑组名、颜色和说明。
- **结果与撤销。** 查看每页的判断与原因，重新判断、重试失败项，或撤销最近一次分组变更。
- **多种模型与读取服务。** 提供常见模型平台预设，支持自定义兼容接口，以及本地、Tavily、DeepSeek 正文读取。
- **统一的界面。** 卡片式侧栏与独立配置页，支持中文、English、浅色、深色和跟随系统。

## 安装

支持 **Chrome 140 或更高版本**。

### 从 Chrome Web Store 安装（推荐）

1. 打开 [AutoTabGroups 商店页面](https://chromewebstore.google.com/detail/onbdjfkcdbialblneckngkhfjdldmgig)。
2. 点击“添加至 Chrome”，在弹出的确认框中选择“添加扩展程序”。
3. 在 Chrome 工具栏的扩展菜单中固定 AutoTabGroups，点击图标打开侧栏。
4. 按下方“快速开始”配置模型服务，即可开始整理。

### 从 Releases 手动安装

需要手动加载或使用指定版本时，可以下载插件 ZIP 安装包：

1. 前往 [Releases](https://github.com/Miraclexc/AutoTabGroups/releases)，下载对应版本的插件 ZIP 附件，不要选择 GitHub 自动生成的 Source code 源码包。
2. 将 ZIP 解压到一个长期保留的文件夹。
3. 打开 `chrome://extensions`，启用右上角的“开发者模式”。
4. 点击“加载已解压的扩展程序”，选择直接包含 `manifest.json` 的解压目录。
5. 在 Chrome 工具栏固定 AutoTabGroups，点击图标打开侧栏。

## 快速开始

1. 从侧栏右上角进入配置页，打开“服务”标签。
2. 在“标准 Chat 服务”中选择平台，填写 API Key。预设会自动填写服务地址、协议和默认模型，模型名称也可自行调整。
3. 将“归组判断服务”设为复用标准 Chat，使用同一套配置完成整理。
4. 点击“测试连接”检查当前输入，再点击“保存配置”使设置生效。
5. 回到待整理的窗口，通过侧栏、右键菜单或快捷键开始整理。

第一次建组时，可以打开至少三个主题相关的页面，使用“更新分组”建立初始组；也可以从“本窗口分组 → 手动建组”选择页面和组名。

## 三个整理动作

| 动作 | 默认快捷键 | 用途 |
| --- | --- | --- |
| **整理当前页** | `Alt+1` | 将当前未分组页面加入合适的已有组 |
| **更新分组** | `Alt+Shift+1` | 将本窗口未分组页面整理到已有组；窗口尚无分组时建立初始分组 |
| **更新并允许新建分组** | `Alt+Shift+2` | 先匹配已有组，再为剩余页面分析并建立新组 |

三个动作在侧栏、网页右键和扩展图标右键中均可使用。快捷键在后台执行，图标角标和悬停文字反馈任务状态。实际绑定可在配置页查看，在 `chrome://extensions/shortcuts` 中管理。

### 整理范围与分组方式

整理以当前普通窗口中尚未分组的 HTTP(S) 页面为对象，由你主动触发。侧栏显示“可整理”和“不参与”的数量，展开后可以查看具体页面与原因。

已有组通过组名和说明表达用途。首次使用缺少说明的组时，模型会参考组名及最多五个成员页面补充说明。你也可以手动编辑说明，或根据组内网页生成新的说明草稿。

明确匹配的页面加入目标组，待确认的页面保持未分组，供你查看结果或手动指定。AI 建立新组需要至少三个明确匹配的有效页面，手动建组支持一个及以上页面。高级设置提供最低归组分数和候选分差，便于调整判断的严格程度。

已经分组的页面保持当前归属，组内浏览和手动移组都沿用你的安排。拖出组的页面，以及从组内打开后落在组外的新页面，会参与下一次整理。

## 侧栏与配置页

### 侧栏：整理与管理分组

| 卡片 | 主要操作 |
| --- | --- |
| **当前页面** | 查看页面标题、来源与分组状态，整理当前页或手动指定分组 |
| **本窗口整理** | 展开页面范围清单，查看数量和原因，执行两个批量动作 |
| **本窗口分组** | 查看分组与成员、定位页面、手动建组，编辑名称、颜色和说明 |

任务运行时显示当前进度，并提供取消操作。任务在扩展后台执行，侧栏可随时打开查看。

### 配置页：服务、偏好与最近结果

配置页在独立标签页打开，分为三个分区：

| 分区 | 内容 |
| --- | --- |
| **常规** | 主题、语言、快捷键、最近整理、使用帮助 |
| **服务** | 标准 Chat、归组判断服务、网页读取、API Key 与连接测试 |
| **高级** | 归组门槛、输入预算、读取超时与兜底、思考参数、备份、缓存与诊断 |

主题和语言即时保存。服务与高级设置共用一份草稿，切换分区后可继续编辑，点击“保存配置”统一生效。

## 模型与网页读取

### 模型服务

标准 Chat 负责理解分组用途、生成说明和规划新组，也可以承担页面归属判断。内置平台预设包括：

**OpenAI、Google Gemini、Anthropic（Claude）、DeepSeek、通义千问（百炼）、Kimi（月之暗面）、智谱（GLM）。**

选择平台后填写对应的 API Key，即可测试连接并保存。模型名称可按账号可用型号调整；自建服务、代理或区域端点可选择 OpenAI 兼容或 Anthropic 兼容方式，填写自己的地址与模型。

归组判断默认复用标准 Chat，也支持独立配置 Chat、Jev 或 OpenAI Decisions。扩展后台直接连接你配置的服务。

### 网页读取

默认使用页面标题、清理后的网址和描述。勾选“读取网页正文”后，可以选择：

| 读取方式 | 配置与用途 |
| --- | --- |
| **内置读取器** | 在浏览器本地提取当前已加载页面的正文，直接使用 |
| **Tavily Extract** | 配置提取接口和独立 API Key，由 Tavily 读取网页 |
| **DeepSeek Fetch** | 配置 Fetch 接口和独立 API Key，由远程服务读取网页 |

远程读取以清理后的网址为输入，返回的正文按长度设置处理后交给模型。默认开启本地兜底：远程读取失败时，依次尝试本地正文和基本描述。正文长度、读取超时、提取深度、输入预算与模型思考参数可在高级设置中调整。

网页读取设置同样作用于生成分组说明时参考的页面。详细参数见[使用指南](docs/user-guide.md)。

## 查看结果与调整归属

在“配置 → 常规 → 最近整理”中展开最近一次任务，可以：

- 查看已归组、保持未分组、已跳过和失败的页面，以及各自原因。
- 展开网页摘录与候选分数，了解模型判断。
- 点击条目定位原标签，或手动选择当前窗口的已有组。
- 对选定页面重新判断，或重试失败项。

侧栏和配置页“常规”均有独立的“撤销最近一次分组”按钮，可撤销当前浏览器会话中最近一次有效分组变更，包括窗口批量整理、单页加入分组，以及任务部分完成时已执行的变更。

重新判断会重新请求模型；撤销会核对页面最新状态，保留你后续的手动安排。分组说明的更新以草稿形式呈现，确认保存后用于后续整理。

## 数据与配置管理

**AutoTabGroups 开发者不收集或接收用户的网页信息、API Key 或使用记录。** 插件不会将这些数据上传至开发者服务器，也不内置使用统计或广告追踪。为提供标签整理功能，插件仍需在本机读取和处理必要的网页信息，并保存配置与任务记录。

配置、密钥、分组说明和最近任务保存在本机扩展存储。整理与说明生成时，所选页面信息发送到你配置的模型服务；选择远程正文读取时，读取服务接收清理后的网址。模型与读取服务按各自 API 规则提供服务和计费。

> **第三方服务隐私提醒：** 标签归组需要调用用户配置的大模型服务。我们无法保证该服务提供商不会收集、记录或留存请求中的信息，是否将其用于训练或其他用途也取决于提供商的政策。使用前请留意所选服务的隐私政策，避免提交不宜向第三方披露的敏感网页信息。

分类缓存保存当前浏览器会话中最多 300 条判断，依据网页信息、模型配置和候选分组内容复用结果。高级设置提供配置与说明的导出、导入预览、缓存清理和诊断；备份包含模型与读取设置及分组说明，API Key 在本机单独管理。

完整的数据范围与权限用途见[数据与权限](docs/privacy.md)。

## 从源码构建

开发环境：**Node.js 22.12+、npm 10+**，推荐 Node.js 24。

```sh
git clone https://github.com/Miraclexc/AutoTabGroups.git
cd AutoTabGroups
npm ci
npm run build
```

构建后，在 `chrome://extensions` 加载 `.output/chrome-mv3`。

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 启动 WXT 开发构建 |
| `npm run check` | 运行类型检查、Lint、单元测试与生产构建 |
| `npm run zip` | 生成插件 ZIP |
| `npm run mock:server` | 启动本地模型 mock 服务 |

项目基于 React、TypeScript、WXT、Zod 和 Chrome Manifest V3，使用 Readability 提取正文。模型请求与分组操作由扩展后台统一处理，测试通过本地 mock 和隔离浏览器运行。
