# 使用指南

[文档首页](README.md) · [安装插件](../README.md#安装)

## 第一次配置

点击工具栏中的 AutoTabGroups 打开侧栏，再从右上角进入独立配置页。配置页有三个标签：

| 标签 | 内容 | 保存方式 |
| --- | --- | --- |
| 常规 | 主题、语言、快捷键、最近整理与帮助 | 主题与语言立即保存 |
| 服务 | 标准 Chat、归组判断、网页读取与密钥 | 点击“保存配置” |
| 高级 | 分数门槛、请求与读取预算、思考设置、备份与诊断 | 与服务标签共用草稿和保存按钮 |

1. 在“服务 → 标准 Chat 服务”选择平台，填写对应的 API Key。插件提供 OpenAI、Google Gemini、Anthropic（Claude）、DeepSeek、通义千问、Kimi 和智谱预设。
2. 检查自动填入的模型名称。可以改为你的服务账号可用的型号；自建服务、代理或不同区域端点使用自定义兼容方式。
3. 在“归组判断服务”保持“复用标准 Chat 服务”，或按[分类接口说明](classifier-backends.md)配置独立服务。
4. 点击“测试连接”检查当前草稿，再点击“保存配置”。测试只发送虚构样例，不保存设置，也不保证实际网页分类一定正确。
5. 回到需要整理的窗口。首次 AI 建组需要至少三个相关页面，也可以先手动建立一个分组。

标准 Chat 用于生成组说明和新组建议，即使分类采用决策模型也需要配置。平台预设会填入模型和思考选项；部分预设使用低档思考，保存前可在高级设置检查，详见[思考设置](model-thinking.md)。

## 地址、密钥和配置草稿

普通 Chat 填写包含版本路径的基础地址：OpenAI 兼容方式追加 `/chat/completions`，Anthropic 兼容方式追加 `/messages`。Jev 和 OpenAI Decisions 填写完整接口 URL，插件按原样请求。

切换到不同域名的平台时，需要填写新平台密钥，草稿不会自动沿用旧平台密钥。未填写新密钥时保留已有保存值；明确点击清除并保存才会删除。切换服务和高级标签不会丢失草稿；关闭页面前应先保存。

测试和保存是两个独立操作，保存不强制联网测试。修改相关字段后，之前的测试结果失效。保存失败会保留输入；多个配置页发生保存冲突时，按提示重载已保存设置后重新编辑。任务运行期间可以修改草稿，需等任务结束后再测试或保存执行配置。

## 选择整理动作

| 动作 | 默认快捷键 | 行为 |
| --- | --- | --- |
| 整理当前页 | `Alt+1` | 将当前未分组页面加入已有组，不建立新组 |
| 更新分组 | `Alt+Shift+1` | 处理本窗口未分组页面；窗口完全没有分组时允许初始化 |
| 更新并允许新建分组 | `Alt+Shift+2` | 先匹配已有组，再为剩余页面考虑新组 |

这些动作可从侧栏、网页右键或扩展图标右键触发。快捷键在后台执行，不自动打开侧栏；图标角标和悬停文字反馈结果。实际按键绑定可在配置页查看，在 `chrome://extensions/shortcuts` 修改。

所有动作只处理触发操作的普通窗口，不跨窗口整理。已分组、固定、无痕和浏览器内部页面不参与自动分类。在侧栏展开“可整理”或“不参与”可查看逐页清单及原因。

一次任务只处理启动时的候选页面。期间新开的页面等下次整理；被关闭、导航或手动改分的页面会在应用前再次检查，避免使用过期判断。重复点击不会并行启动多个任务。

## 分组名称与说明

组名表达主题，说明用于界定范围。例如“开发”较宽泛，“插件开发”配合“浏览器扩展 API、开发教程及调试问题”更容易与其他组区分。

你可以在“本窗口分组”中编辑名称、颜色和说明。手动建组只需选择至少一个页面并填写组名，说明可以留空。整理时发现已有组缺少说明，标准 Chat 会参考组名和最多五个组内页面自动补齐；参考页同样遵循正文读取设置。

“根据组内网页更新说明”生成可编辑的草稿，保存后才用于后续分类。成员变化不会自动覆盖已保存说明。生成说明失败时，任务会给出错误，不会把实际存在的组当作不存在。

插件使用浏览器的真实分组。同名组仍各自独立，手动重命名、换颜色、移组或删除组会反映到插件中。关闭分组后，已保存说明可以保留，但不会单凭说明重新打开网页或创建同名组。

## 网页读取

默认关闭“读取网页正文”，仅使用标题、清理后的网址与页面描述，不先让 AI 总结网页。开启正文后可选择：

| 方式 | 信息来源 | 需要配置 |
| --- | --- | --- |
| 内置读取器 | 当前浏览器已加载页面，通过 Readability 提取主要文本 | 无额外密钥 |
| Tavily Extract | 远程服务读取清理后的网址 | 完整提取接口、独立密钥，可选提取深度 |
| DeepSeek Fetch | 远程服务读取清理后的网址 | 完整 Fetch 接口、独立密钥 |

内置读取排除表单与可编辑区域。没有可用正文时退回基本信息；休眠、冻结或无法访问的页面也尽量用标题和网址处理，不强行唤醒。

远程读取不发送浏览器 Cookie，因此登录后页面的远程结果可能与当前页面不同。默认允许本地兜底：远程失败后尝试本地正文，再退回基本信息；关闭兜底时该页读取失败，不继续分类。取消任务不会触发继续读取。

“测试读取接口”请求公开的 example.com，不读取当前标签，也不保存设置。它会真实调用所配置的服务，可能计费。正文长度限制同样适用于本地、远程以及生成组说明的参考页。数据发送范围见[数据与权限](privacy.md)。

## 高级设置

| 设置 | 初始值 | 影响 |
| --- | --- | --- |
| 最低归组分数 | 0.8 | 所选组低于门槛时保持未分组，可调整至 0 |
| 最小候选分差 | 0.2 | 所选组与其他候选（含无合适组）的分数差不足时保持未分组 |
| 单次最多建议新组数 | 8 | 限制建议数量，不放宽新组所需成员数量 |
| 每页正文字符上限 | 6000 | 限制送入模型的正文长度 |
| 请求输入预算 | 30000 UTF-8 字节 | 限制请求输入大小，不是精确 token 计数 |
| 远程读取超时 | 20 秒 | 控制读取接口的等待上限 |
| Tavily 提取深度 | 标准 | 可切换深度提取，响应时间和额度消耗取决于服务 |
| 远程失败时本地兜底 | 开启 | 远程读取失败后尝试浏览器内提取 |
| 思考适配与强度 | 自动、关闭 | 普通 Chat 的思考控制；选择平台预设可能填入不同强度 |

AI 建立新组要求最终至少三个仍可操作、明确匹配的页面。降低分数门槛不会取消这项要求，也不会迫使模型放弃“无合适组”。候选分数的含义与调节示例见[模型与分类接口](classifier-backends.md)。

## 进度、结果与手动纠正

任务运行时显示进度条、当前阶段、已处理数量、当前页面和归组／失败数量。需要一次等待整体结果的准备、规划阶段使用等待动画，不提供预计剩余时间。关闭侧栏不等于取消任务；需要停止时使用“取消任务”。

在“常规 → 最近整理”展开最近一次结果，查看已归组、保持未分组、跳过和失败的页面。每页可查看有限的网页摘录及前三个候选分数；结果是任务执行时的记录，之后手动移动不会改写这份记录。插件不累积完整任务历史。

- 点击页面标题定位原标签。
- 手动选择当前窗口的已有组，不调用模型。
- “重新判断”绕过该页缓存，重新请求分类。
- “重试失败项”沿用原动作的操作范围和新建权限。
- “清除任务详情”只清除最近结果，不移动标签，也不删除独立的撤销记录。

## 撤销、缓存与重启

侧栏和配置页均提供“撤销最近一次分组”，两处对应同一条最近有效操作，包括批量整理、单页归组和插件内手动建组或移组。无变更任务不会覆盖上一条撤销；取消或部分失败后，已完成的变更仍可撤销。已关闭、导航或被用户再次改分的页面会保持现状。撤销仅适用于当前浏览器会话。

分类结果在当前浏览器会话缓存最多 300 条，不按固定时间过期。网页信息、模型配置或候选组含义变化时重新判断；只调整阈值时，可对缓存分数重新判定。命中缓存仍会核对标签和目标组状态。

浏览器重启后，插件会识别浏览器实际恢复的组，尽可能关联保存的说明。同名存在歧义时不强行合并；插件本身不负责恢复网页。上次浏览器会话中未完成的任务不会继续操作新会话，需重新发起整理。意外关闭后的注意事项见[常见问题](troubleshooting.md)。

## 主题与语言

“常规 → 外观与语言”支持浅色、深色、跟随系统，以及中文／English。选择立即保存并同步到已打开的插件页面；默认跟随系统主题、中文。

界面、状态和确认框跟随当前语言。AI 新生成的名称和说明沿用任务启动时的语言；已有分组、用户输入、网页内容和第三方原始错误不会自动翻译。Chrome 管理页中的扩展名称和快捷键说明跟随浏览器语言。

可以用 Tab 切换控件、Enter 激活操作或展开详情、Escape 关闭弹窗。有未保存内容时会先确认；系统减少动态效果设置会关闭非必要过渡。

## 备份与更新

在“高级 → 数据与诊断”导出设置和分组说明。备份不包含 API Key、原生标签／组 ID 或完整正文；导入先显示差异，确认后更新设置并合并说明，不移动标签或打开网页。导入后请单独配置所需密钥。

更新插件时保留原安装，不要先卸载；卸载会清除本地扩展数据。旧格式任务记录不展示或恢复，设置与分组说明继续保留。清除分类缓存不会改变分组，只会让后续判断重新请求模型。
