# 架构说明

[文档首页](README.md) · [开发指南](development.md)

AutoTabGroups 是基于 Chrome Manifest V3 的浏览器扩展，使用 React 和 TypeScript 构建界面，WXT 负责入口与产物构建。扩展没有独立业务服务器：页面提取在浏览器内执行，模型与可选读取服务由后台直接访问，分组由 Chrome 原生 API 管理。

## 模块与职责

| 模块 | 职责 | 主要入口 |
| --- | --- | --- |
| 界面 | 侧栏操作、配置草稿、任务结果与纠正操作 | [App.tsx](../src/ui/App.tsx)、[Configuration.tsx](../src/ui/Configuration.tsx) |
| 后台入口 | 统一处理 UI、快捷键、右键菜单和恢复事件 | [background/index.ts](../src/entrypoints/background/index.ts) |
| 命令控制器 | 校验命令、处理配置与手动操作、返回状态 | [controller.ts](../src/workflows/controller.ts) |
| 任务编排 | 页面读取、判断、应用、取消、检查点与恢复 | [organizer.ts](../src/workflows/organizer.ts) |
| 网页读取 | 注入、页面身份检查、元数据、Readability 与远程读取 | [injection.ts](../src/browser/injection.ts)、[extraction](../src/extraction) |
| AI 接口 | 请求预算、协议适配、分类校验、提示词与思考参数 | [ai](../src/ai) |

## 入口与消息边界

`entrypoints/background` 注册 UI、commands、contextMenus 和恢复 alarm。三种来源调用同一个 Organizer。只有受信的 sidepanel/options 页面可发送 UI 命令；网页内容不能调用模型或读取密钥。

业务契约位于 [shared/organizer.ts](../src/shared/organizer.ts)。UI 通过 `dispatch` 发送命令，后台使用 `organizerCommandSchema` 校验。成功响应为 `{ ok: true, data }`，失败为 `{ ok: false, error }`；应用错误使用消息码和参数，界面按当前语言渲染。

命令按职责分为状态查询、整理与重试、取消与撤销、配置保存与连接测试、手动建组与移组、说明编辑与生成、导入导出与数据维护。执行模型请求与原生变更的权限留在后台，内容脚本只返回提取结果。

## 三种命令与权限

- organize-current：一个未分组标签，不能新建。
- organize-window：当前窗口未分组，只有启动时实际零组才可初始化。
- organize-window-with-new：已有组优先，剩余标签可规划新组。

命令固定窗口、成员快照、初始组结构、设置与新建原因。全扩展同时只运行一个任务。组事件同步名称和关联，无 AI；标签事件只驱动界面刷新。

运行中的任务不吸收后来打开的标签，也不接受后来保存的执行设置。重试从原任务中选择允许重试的条目，沿用原动作的新建权限；手动移动有独立命令，不通过模型输出扩大自动整理范围。

## 模型与执行

准备描述 → 已有候选分类 → 应用已有组 → 如有权限，为剩余标签规划新组 → 已有和新候选共同分类 → 最终数量复核 → 新建。

| 阶段 | 工作与约束 |
| --- | --- |
| `prepare` | 读取当前原生组，补齐缺失说明，确定实际候选 |
| `existing` | 读取页面并匹配已有组，保存分类结果与分数 |
| `apply-existing` | 重新核对标签身份和目标组后应用已有组 |
| `plan` | 仅在允许新建且剩余页面满足条件时规划新组 |
| `final` | 使用已有组与新建议共同复核剩余页面归属 |
| `apply-final` | 检查组结构和最终有效成员数，再执行新建与归组 |
| `done` | 保存最终结果、撤销记录和诊断，释放任务锁 |

分类错误与操作错误写入相应条目；配置或鉴权等错误可终止任务。终态包括完成、部分成功、取消、中断和失败。低分、无合适组等正常判断保持未分组，不伪装为成功移动。协议与分数规则见[模型与分类接口](classifier-backends.md)。

标准 Chat 负责描述与规划。归组判断保留普通 Chat / Jev / Decisions。规划引用必须有效、不重复，每建议至少 3 个支持标签，不接收兜底组或重复名称。应用时再次按明确最终成员计数。

`joinExisting` 必须使用原生目标 ID，无创建兜底；`createNative` 单独要求明确的数量与结构核对。手动建组通过单独的可信命令采用最小 1 页，不是模型响应可获得的权限。

## 存储和关联

| 存储位置 | 键 | 内容与生命周期 |
| --- | --- | --- |
| `chrome.storage.local` | `workspace.v2` | 设置、分组说明档案与配置修订号 |
| `chrome.storage.local` | `credentials.v1` | 标准 Chat、独立分类及两种读取服务的密钥 |
| `chrome.storage.local` | `ui.preferences.v1` | 主题和界面语言 |
| `chrome.storage.local` | `organizer.task.v3` | 最近任务、阶段、输出语言、逐页结果与操作日志 |
| `chrome.storage.local` | `organizer.undo.v2` / `organizer.pending.v2` | 最近有效撤销与尚待确认的变更意图 |
| `chrome.storage.local` | `organizer.diagnostic.v3` | 最近一次触发的来源、动作、时间和结果 |
| `chrome.storage.session` | `sessionId` | 本浏览器会话身份，用于阻止跨会话重放 |
| `chrome.storage.session` | `organizer.links.v2` | 原生组 ID、窗口与说明档案的关联 |
| `chrome.storage.session` | `organizer.decisions.v2` | 当前会话内的分类缓存 |

组候选使用原生组独立引用，同名组不会折叠。说明档案使用自己的稳定 ID，不把重启后可能变化的 Chrome 组 ID 当作永久身份。已有会话关联优先；重建时仅接受无歧义的当前名称或历史名称匹配。实际组的重命名与颜色更新会同步到说明档案，组删除不会触发重建网页。

配置迁移读取旧 config.v1 与 groupHints.v1，保留原 ID、说明、模型和凭据，旧数据不覆盖。只有无歧义的名称或历史名才能重建关联；否则为实际组创建待补充说明记录。不读取、显示或迁移旧 task.v1 / organizer.task.v2 任务记录。

配置保存按 `revision` 防止并发覆盖，通过一次存储操作写入设置与相关密钥。导出格式由 `backupSchema` 定义，只包含设置与说明；导入先预览差异，确认时再次校验修订号，不导入密钥、原生身份或操作日志。

## 缓存

会话键 `organizer.decisions.v2`，最多 300 条，无固定时间过期。键包含实际网页输入、有效分类模型、按稳定 ID 排序的候选名称说明、语义版本。阈值、颜色和源分组位置不参与语义键；阈值对缓存分数重新执行。损坏条目作为缓存未命中。

不存完整正文，保留分类分布；用户重新判断可绕过。新候选集合需要新的判断。缓存键哈希是运行机制，不是文件完整性校验。

## 任务、恢复与撤销

organizer.task.v3 保存阶段、分类结果、快照、规划、输出语言及逐标签日志；应用提示保存为消息码与参数，不保存凭据或完整正文。只恢复当前版本记录，恢复跳过已完成分类与应用。浏览器新会话把上次会话尚在运行的当前版本任务标记中断。升级前的旧格式任务不恢复；现有分组、配置、密钥及独立的撤销日志不受此变更影响。

organizer.undo.v2 与最近任务独立。写入前 pending 日志保留操作意图，实际变更后提交有效撤销；无变更任务不替换旧撤销。无法确认的写入不重放。Chrome 和存储不是原子事务，无法保证严格一次执行。

手动移动记录原组，只有本操作实际移走最后成员才允许撤销重建原组；用户之后修改的标签跳过。

## 界面状态与多语言

侧栏围绕当前页、窗口更新和真实分组提供操作；options 管理常规、服务、高级配置，并在常规中提供最近整理详情与纠正操作。侧栏不重复显示结果列表。状态刷新合并，表单脏状态独立，带配置版本防止覆盖。模型测试使用草稿，不保存；延迟返回不能把已修改草稿标为测试成功。导入按预览版本应用。

视觉变量与共用控件位于 `styles.css` / `components.tsx`，侧栏与配置页分别维护布局。`ui.preferences.v1` 独立保存主题和语言，通过后台验证、串行合并局部更新，不推进模型配置版本；两类页面监听同一存储变化。`i18next` / `react-i18next` 使用打包在扩展内的中英文词条；消息码在显示时按当前语言解析，保留用户标题、描述及第三方原始错误原文，不做中文字符串匹配。右键菜单与后续任务提示读取同一语言偏好。Chrome 原生名称、简介与快捷键文案由生成的 `_locales` 跟随浏览器语言。实现与贡献约定见[多语言开发](i18n.md)。

AI 系统提示词统一使用英文，包括 OpenAI 兼容 Chat 的 system 消息、Anthropic 兼容 Chat 的 system 字段，以及 Jev / Decisions 的 instructions。生成任务通过 `output-language.ts` 指定自然语言输出为中文或英文；JSON 键、颜色枚举、候选键和标签 ID 不翻译，网页与既有分组数据按原文传入。中文组名建议 2–6 字、最多 8 字符；英文建议 1–3 词、最多 24 字符，这些是提示词约束。

整理开始时将语言偏好持久化为任务的 `outputLocale`，补全描述和新组规划共用此值，同一会话恢复时沿用。该字段为必填。手动生成描述和连接测试读取调用时的偏好。切换语言不批量翻译或重命名已有分组；分类只返回固定候选键与分数，无需翻译。改变分类提示词的语义时应同步更新缓存语义版本。

读取序号防止旧请求覆盖新状态；被后续读取取代的调用等待实际展示的读取结果。保存已提交而读取失败时保留输入，提供仅重新读取的恢复操作，不重复提交保存。模态集中管理焦点循环、Escape、焦点恢复和嵌套滚动锁。

Organizer的锁状态转换通过注入回调广播 `organizer-state-changed`。UI验证扩展发送方后仅触发状态重读，不依据通知载荷直接修改busy。通知失败与无人监听不影响操作；锁保持到任务收尾完成后释放，随后广播，避免最后一次存储事件早于实际释放而使界面停在禁用状态。

## 页面提取与读取服务

元数据提取支持多源标题摘要、实时 DOM、YouTube 视频身份与抖音面板身份。只处理文本信息，不处理封面、媒体或收藏。轻量模式不扫描正文摘要，正文模式继续使用 Readability。超时包含 executeScript 与消息全程。提取及执行均核对页面身份。

settings.reader 保存服务选择、各服务端点、Tavily 深度、请求超时和本地兜底策略。旧配置解析时补齐本地默认值；新任务保存完整设置快照，旧格式任务不读取。credentials.v1 独立保存 tavily/deepseek 键，workspace-state 仅返回存在标记，保存与模型设置共用原子存储写入。

browser/injection.ts 区分基本、本地正文、远程正文。extraction/remote.ts 只处理官方读取协议，不经 Chat 提示词；进行鉴权、超时、响应结构和 URL 对应校验。取消与页面变更均中止应用；远程失败按显式策略兜底，描述参考页共用同一路径。test-reader 只对 example.com 测试，不保存、不回退。缓存基于最终实际内容，读取来源进入已有 PageInput。

## 数据边界与扩展方式

密钥和存储只开放给受信扩展上下文。网页、组名与组说明都视为不可信资料；提示词将它们与指令分开，响应仍必须通过本地结构与语义校验。分组权限、窗口范围、三页新建门槛和操作前复核由程序决定，模型不能覆盖这些规则。

新增分类服务时实现统一分类契约并接入工厂；新增读取器时保持 `PageInput` 的来源与截断标记，以及取消、导航核对和回退行为。新增持久化字段需说明生命周期，避免将完整正文或密钥带入任务结果和导出。相关检查方法见[测试指南](testing.md)，用户可见的数据约定见[数据与权限](privacy.md)。
