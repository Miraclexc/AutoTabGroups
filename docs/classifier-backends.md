# 模型与分类接口

[文档首页](README.md) · [使用指南](user-guide.md) · [架构说明](architecture.md)

本文先说明用户配置，再说明开发者需要遵守的请求与响应契约。标准 Chat 负责分组说明和新组规划；归组判断负责从已有候选中选择一个组或保持未分组。默认复用标准 Chat，也可以在“服务 → 归组判断服务”关闭复用后选择独立后端。

## 配置与地址

| 后端 | Base URL 示例 | 地址处理 | 模式 |
| --- | --- | --- | --- |
| Jev | `https://api.typesafe.ai/v1/systemone` | 原样请求 | 原生 choice |
| OpenAI Decisions | 完整 Decisions 接口地址 | 原样请求 | 原生 choice，与 Chat 协议不同 |
| 普通大模型 · OpenAI 兼容 | 服务商版本路径 | `/chat/completions` | JSON 分类，需支持 `response_format: json_object` |
| 普通大模型 · Anthropic 兼容 | `https://api.anthropic.com/v1` | `/messages` | 最终文本中的 JSON 分类 |

型号能否使用取决于实际接口、账号权限和网关支持。这里描述插件已实现的协议，不维护服务商的实时模型目录。填写地址时不要附带用户名、密码、查询参数或 URL 片段；密钥填写在独立输入框中。

切换独立分类后端时保留地址、模型名和已存密钥，请逐项检查后测试与保存。插件保存一套独立分类配置，不为每种后端分别保存多套凭据。决策模型地址不自动追加或补全路径，末尾斜杠也保持原样；只有 `/v1` 的基础地址通常不足以指定决策接口。普通 Chat 按所选协议追加路径，不要在基础地址中重复填写 `/chat/completions` 或 `/messages`。

独立普通 Chat 分类可配置 GPT、Claude、DeepSeek、GLM、Kimi 等对应兼容服务，并独立设置思考适配方式和强度，基础默认值为关闭。独立模式不使用标准 Chat 的思考设置；Jev 和 Decisions 都不发送普通聊天模型的思考参数。适配规则见[思考设置](model-thinking.md)。

复用标准 Chat 时，分类请求使用标准 Chat 的模型、密钥和思考设置；只有独立配置普通 Chat 分类时，两套思考设置才相互独立。

## 输入和语义规则

每次判断都提供页面标题、URL、描述，以及用户启用时的 Readability 正文；直接分类，不生成页面摘要。所有分类的名称、描述、包含和排除条件同时传入。候选仅额外含 `none`，统一表示没有合适分类或信息确实不足，允许页面保持未分组。

三种后端共用语义规则：标题和 URL 足够明确时即可分类，不因缺少正文、空描述或提取失败直接拒绝；允许中英文、同义词和子主题匹配，避免偶然关键词或同域名造成误归组。名称和描述共同界定范围，名称单独提供时按通常含义判断；包含项是非穷尽示例，排除项是明确边界。多个候选相关时优先直接、具体的匹配，分数应反映实际不确定性，不为通过阈值虚增分数。

系统指令统一英文。网页与组信息保持原文，按不可信数据传入；模型不能通过这些字段获得修改窗口范围、新建门槛或操作权限的能力。新组名和说明的语言由任务输出语言控制，分类候选键不翻译。

## 候选分数与归组门槛

Jev / Decisions 使用接口返回的候选概率；普通大模型使用提示词要求的归一化自评分。后者在结果中显示“模型自评分”，不能视为经过校准的概率或真实正确率。最低分数、第一与第二名分差均参与自动归组；`confidence` 不替代候选分数。两个决策接口的概率也需结合实际样本评估阈值。

响应必须包含完整候选分布、合法取值、总和约为 1，以及与最高分一致的选择。拒绝回答、截断、无效 JSON、未知分类或非法分数会让该条记录失败并保持未分组，其他页面继续处理；不会静默切换后端。明确不匹配及低分在页面上统一显示为未匹配，统计合并计算；具体原因仍可在处理详情中查看。

默认最低分数为 0.8，最小分差为 0.2，两者都可以在高级设置中调整至 0。例如某组 0.72、另一个组 0.18、`none` 为 0.10：最低分数设为 0.8 时不归组，设为 0.7 且分差门槛为 0.2 时可归组。即使两个门槛均为 0，模型选择 `none` 时仍保持未分组。

缓存键包含后端、协议、地址、模型、思考配置、页面和分类规则；切换会使用不同缓存。缓存保存分数来源，读取缓存后仍区分自评分与概率。

更新结果展示实际分类中分数最高的三个候选，横向一行按原始分数降序显示“颜色方块 分组名 百分比”，不对前三名重新归一化；不把 none 当作分组列入前三。少于三个分类时显示实际数量。分数、当时的分类名和颜色随任务记录保存；最近结果使用保存的候选信息，候选缺失颜色时使用灰色。长名称省略显示，悬停可查看完整名称、分数及分数来源。失败未获得响应或当前任务没有候选分数时显示暂无候选分数，不伪造零分。

## 开发者接口契约

分类工厂位于 [classifier.ts](../src/ai/providers/classifier.ts)，三个后端都实现 [TabClassifier](../src/ai/contracts.ts)。输入为 `PageInput`、候选 `Category[]` 和可选 `AbortSignal`；输出统一为 `Classification`：

```ts
interface Classification {
  choice: string;
  probabilities: Record<string, number>;
  confidence: number;
  model: string;
  scoreSource?: 'decision_probability' | 'llm_estimate';
}
```

请求使用 `group_0`、`group_1` 等临时候选键，响应校验后再映射为本地组 ID；额外候选只有 `none`。名字只是资料，不能代替稳定键。完整候选生成与校验见 [choices.ts](../src/ai/providers/choices.ts)。

| 后端 | 请求结构 | 响应读取 |
| --- | --- | --- |
| Jev | `model`、`state: page`、`questions.route: { type: 'choice', instructions, criteria }` | `model` 和 `answers.route` 中的选择、分数映射与置信值 |
| Decisions | `model`、`input: JSON.stringify(page)`、`questions: [{ type: 'choice', name: 'route', instructions, choices }]` | 唯一的 `answers` 条目；候选概率数组转为映射，拒答单独报错 |
| 普通 Chat | 英文 system 指令与包含 `page` / `choices` 的 user JSON | 最终文本中的 JSON，区分 OpenAI 与 Anthropic 响应结构 |

普通 Chat 最终文本中的分类对象示例：

```json
{
  "choice": "group_0",
  "probabilities": { "group_0": 0.85, "group_1": 0.10, "none": 0.05 },
  "confidence": 0.85
}
```

所有候选必须恰好出现，分数在 0–1 之间，总和与 1 的误差不超过 0.02；选择项不能低于最高分（数值比较允许 0.0001 浮点误差）。`confidence` 保留在结果中，但自动归组使用候选分数与分差。不能用部分候选、重新归一化前三名或无效响应补零来绕过校验。

## 传输、失败与扩展

共用传输层 [transport.ts](../src/ai/transport.ts) 对每次 fetch 设置 20 秒超时，429/5xx 最多重试一次，不跟随重定向。401、400 等配置错误不会自动移除参数重试；响应正文不直接暴露在错误提示中。取消通过 `AbortSignal` 向下传递。

新增后端应复用候选与分布校验，明确 `scoreSource`，保持 URL、模型和凭据的独立性。分布解析成功后仍需通过本地分数策略及浏览器状态复核，不能直接操作标签。请求预算按 UTF-8 字节核算，超预算应显式报错或使用既定的输入裁剪规则。

可重复的本地验证方法见[测试指南](testing.md)，本地 mock 地址见[开发指南](development.md#本地-mock-调试)。这些检查验证客户端契约，不代替真实服务账号与语义效果评估。
